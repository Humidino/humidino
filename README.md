# humidino

Прошивка ESP32-S3 для автоматического контроля микроклимата и вентиляции подпола: опрос 4 датчиков SHT-30 на двух шинах I2C, расчёт точки росы и абсолютной влажности, управление вытяжным SSR-реле по алгоритму осушения (с защитой от конденсата и замерзания, антидребезгом), дашборд на LVGL/TFT_eSPI (480x320, ILI9488), локальный веб-интерфейс, MQTT с Home Assistant discovery.

## Сборка

```bash
pio run -e esp32-s3-devkitc-1
```

Прошивка (после подключения платы):

```bash
pio run -e esp32-s3-devkitc-1 -t upload
pio run -e esp32-s3-devkitc-1 -t uploadfs   # веб-интерфейс (data/index.html) на LittleFS
pio device monitor
```

## Что не проверено на реальном железе

Весь код собирается без ошибок (RAM ~30%, Flash ~39% от раздела приложения), но **ни разу не прошивался и не тестировался на физической плате** — я работал без доступа к устройству. Перед вводом в эксплуатацию обязательно проверить:

- Ориентацию/поворот дисплея (`g_tft.setRotation(1)` в [display.cpp](src/display.cpp) — может потребовать 0/2/3).
- Реальную работу PSRAM (сборка использует вариант `qio_opi`, но фактическая инициализация проверяется только на плате).
- Корректность пина MISO дисплея (не задействован физически, см. комментарий в [User_Setup.h](include/tft_config/User_Setup.h)).
- Тайминги min-runtime/min-pause удобно на первое время уменьшить в [config.h](include/config.h) для ускоренной стендовой проверки state machine реле.
- Юнит-тесты `climate_math` (`pio test -e native`) требуют локального gcc/g++ (не установлен в этом окружении) — формулы проверены вручную (см. историю сессии), но тест-раннер не запускался.
